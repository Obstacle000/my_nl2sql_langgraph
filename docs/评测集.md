# 评测集（Eval）

> 目的：用一个固定问题集，量化「生成 SQL 的执行结果是否正确」，而不是看 SQL 写得像不像。
> 脚本：[`eval/run_eval.py`](../eval/run_eval.py)｜用例：[`eval/qa_set.yaml`](../eval/qa_set.yaml)｜报告：`eval/report.json`

---

## 一、两类测试别混

| | 评测集（accuracy） | 单元测试（pytest） |
| --- | --- | --- |
| 测什么 | 端到端「答案对不对」 | 单个函数/契约 |
| 依赖 | MySQL / Qdrant / ES / LLM 都要在 | 纯函数不需要 |
| 频率 | 每次改 prompt/召回后跑 | 每次提交跑 |
| 指标 | 准确率、p95 延迟 | pass/fail |

```text
单元测试优先覆盖纯函数：normalize_question / cosine / clean_sql / _safe_col / _sql_type
评测集覆盖业务能力：单表聚合 / 分组排序 / 多表关联 / 时间窗口 / 边界
```

## 二、怎么造用例

### 从 schema 出发，不要从问题出发

```text
① 先看表结构，列"能力清单"：单表聚合、分组+排序、多表 join、时间过滤、边界
② 每类挑 10 个典型问法（业务口吻，不出现字段名）
③ 每条写 gold SQL，并**在库里跑通**
④ 记录 id / category / question / gold_sql
```

### 三条硬规则

```text
① 可判定：结果稳定，别写"最近 30 天"，写"2025 年 3 月"
② 单一意图：一条只测一件事（"销售额和订单数"算两条）
③ 歧义要消：写清"按销售额"还是"按销量"
```

### 一条用例的样子

```yaml
- id: t01
  category: 时间窗口
  question: 2025年1月的总销售额是多少
  gold_sql: >
    SELECT SUM(f.order_amount) AS total_amount
    FROM fact_order f JOIN dim_date d ON f.date_id = d.date_id
    WHERE d.year = 2025 AND d.month = 1
```

```text
gold_sql 只求结果正确，不要求和模型生成的写法一致
（模型用 date_id BETWEEN 也可以，只要结果一致）
```
```text
sql分类:

单表聚合   → 最基础，召回对字段就能过；过不了说明字段没找对
分组排序   → 测"维度 + 度量"的区分能力（GROUP BY 谁、SUM 谁）
多表关联   → 测 join 路径；这是 schema linking 的核心难点
时间窗口   → 测日期字段的类型/用法（这次全挂在这）
边界       → 测空结果、口径歧义，防止"看起来对"
```

## 三、怎么判定对错

**比对“结果集”，不比对 SQL 文本。**

```python
def normalize(rows):
    out = []
    for row in rows:
        cells = []
        for v in row.values():
            if v is None:
                cells.append("0")                      # SUM 空集返回 NULL
            elif isinstance(v, (int, float, Decimal)) and not isinstance(v, bool):
                cells.append(f"{round(float(v), 2):.2f}")   # 浮点容差
            else:
                cells.append(str(v).strip().lower())   # 字符串忽略大小写
        out.append(tuple(cells))
    return sorted(out)                                  # 行顺序不算错
```

四个坑：

```text
① Decimal：DB 的 SUM 返回 Decimal('622')，不转 float 会判和 622.0 不等
② NULL：SUM/AVG 空集返回 NULL，模型可能返回 0 或空列表 → 统一按 0
③ 行顺序：ORDER BY 不一致不该算错 → 排序后比
④ 列名：别名不同不该算错 → 只比值
```

```text

```

### 失败案例（12/16 都是日期字段语义）

```text
真实结构：
  dim_date(date_id int  ← 20250101 这种整数
           year, month, quarter  ← 已拆好)

模型生成：
  DATE_FORMAT(order_date, '%Y-%m')          ← 字段根本不存在
  EXTRACT(MONTH FROM dd.date)                ← dd.date 不存在
  JOIN dim_date ON fact_order.date_id = dim_date.id   ← id 不存在，是 date_id
  WHERE DATE(order_id) = '2025-01-01'        ← 把订单号当日期
```

其他失败：

```text
t10：生成的 SQL 被截断 / 混入解释文字
e04："销量最低的品类" → 生成 MIN(order_quantity)（单笔最小值），
     正确是"先按品类 SUM 再取最小"
```

## 六、失败归类（每次跑完都要做）

```text
执行失败（SQL 报错）     → 字段名/join 编造      → 补字段描述、加字段白名单
结果为空                 → 值或时间条件错        → 值域召回、日期字段说明
结果不一致（都有数）     → 口径错                → 指标定义、prompt 约束
含解释文字/被截断        → 解析问题              → clean_sql、prompt 强调纯文本
```
