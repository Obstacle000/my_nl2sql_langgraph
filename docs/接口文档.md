## 1. 通用约定

```text
前缀：/api
编码：JSON（上传接口用 multipart/form-data）
时间：秒级时间戳（BIGINT）
鉴权：Authorization: Bearer <access_token>
版本：MVP 不带版本号
```

### 1.1 鉴权（两层）

```text
第一层（main.py 中间件）：所有请求都解析 token
  · 有效 → user_id 写入 ContextVar，快过期则续签（响应头 X-New-Token）
  · 无效/缺失 → 不报错，按未登录处理
第二层（路由参数 user_id: CurrentUser）：需要登录的接口校验，空则 401
```

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

| 情况 | 返回 |
| --- | --- |
| 未带 token 访问受保护接口 | 401 `{"detail": "登录已失效，请重新登录"}` |
| token 过期/签名错 | 401 `{"detail": "登录已失效，请重新登录"}` |

**续签**：token 剩余 < 15 分钟时，响应头会带 `X-New-Token`，前端替换本地 token 即可。

### 1.2 错误响应

```json
{"detail": "数据集不存在"}
```

| 状态码 | 含义 | 场景 |
| --- | --- | --- |
| 400 | 参数非法 | CSV 解析失败、连接失败、缺必填配置 |
| 401 | 未认证 | 无 token / token 失效 |
| 404 | 不存在或无权访问 | 数据集/数据源不属于当前用户 |
| 409 | 冲突 | 用户名已存在 |
| 422 | 校验失败 | Pydantic 字段不合法（FastAPI 自动） |
| 500 | 服务端异常 | 未捕获异常（如索引构建失败） |

> **安全约定**：越权一律 404，不用 403——避免暴露“资源存在但你不能看”。

## 2. 账号

### 2.1 注册（免登录）

```http
POST /api/auth/register
Content-Type: application/json
```

```json
{"username": "alice", "password": "123456"}
```

校验：username 3~32 字符；password 6~64 字符。

```json
// 200
{"username": "alice"}
```

```json
// 409
{"detail": "用户名已存在"}
```

### 2.2 登录（免登录）

```http
POST /api/auth/login
Content-Type: application/json
```

```json
{"username": "alice", "password": "123456"}
```

```json
// 200
{"access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "token_type": "bearer"}
```

```json
// 401
{"detail": "用户名或密码错误"}
```

> 有效期 120 分钟（`conf/app_config.yaml` → `auth.access_token_minutes`）。

## 3. 数据源

### 3.0 两个创建入口的分工

| 来源 | 入口 | 数据源 | 数据集 |
| --- | --- | --- | --- |
| MySQL | `POST /api/datasources` | 显式创建（加密 config） | 同请求创建，同步 schema |
| CSV | `POST /api/datasets` | 隐式创建（kind=csv） | 同请求创建，空表集 |

> CSV 建完还要调 `POST /api/datasets/{id}/tables` 逐张上传。

### 3.1 探测（测试连接 + 返回表清单）

```http
POST /api/datasources/probe
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "kind": "mysql",
  "config": {
    "host": "10.0.0.5",
    "port": 3306,
    "user": "readonly",
    "password": "***",
    "database": "shop"
  }
}
```

```json
// 200
{
  "ok": true,
  "database": "shop",
  "tables": [
    {"name": "orders",   "columns": 8},
    {"name": "refunds",  "columns": 5},
    {"name": "products", "columns": 12}
  ]
}
```

```json
// 400（连接失败，返回可读原因）
{"detail": "连接失败：Access denied for user 'readonly'@'10.0.0.9' (using password: YES)"}
```

> **不落库**：只连一次、读一次 `information_schema`、随后释放连接。

### 3.2 创建 MySQL 数据源（+ 数据集）

```http
POST /api/datasources
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "kind": "mysql",
  "name": "公司订单库",
  "config": {
    "host": "10.0.0.5",
    "port": 3306,
    "user": "readonly",
    "password": "***",
    "database": "shop"
  },
  "dataset": {
    "name": "销售分析",
    "description": "订单与退货",
    "tables": ["orders", "refunds"]
  }
}
```

```json
// 201
{
  "datasource_id": 1,
  "dataset_id": 1,
  "tables": 2,
  "columns": 13,
  "status": "ok"
}
```

后端动作：

```text
加密 config → 测试连接 → 建 dataset → 只登记选中的表
→ 写 table_info / column_info → 建 Qdrant 向量 + ES 取值索引 → status=ok
```

> `dataset.tables` 为空/不传时，登记该库全部表。

### 3.3 数据源列表

```http
GET /api/datasources
Authorization: Bearer <token>
```

```json
// 200
{
  "datasources": [
    {
      "id": 1,
      "kind": "mysql",
      "name": "公司订单库",
      "status": "ok",
      "last_checked": 1761750000,
      "config_preview": {"host": "10.0.0.5", "port": 3306, "database": "shop"}
    },
    {
      "id": 2,
      "kind": "csv",
      "name": "电商订单",
      "status": "ok",
      "last_checked": null,
      "config_preview": {}
    }
  ]
}
```

> **永远不返回 password**；CSV 类型 `config_preview` 为空对象。

### 3.4 测试已有数据源

```http
POST /api/datasources/{id}/test
Authorization: Bearer <token>
```

```json
// 200（成功）
{"ok": true}
```

```json
// 200（失败也返回 200，由 ok 表达，便于前端展示原因）
{"ok": false, "error": "连接超时（30s）"}
```

> CSV 数据源返回 `{"ok": true, "message": "CSV 数据源无需连接"}`。

### 3.5 同步 schema

```http
POST /api/datasources/{id}/sync
Authorization: Bearer <token>
```

```json
// 200
{
  "dataset_id": 1,
  "added_tables": 2,
  "removed_tables": 0,
  "changed_columns": 0,
  "schema_version": 2
}
```

```text
动作：重新 discover → 登记新增的表 → schema_version += 1 → 建索引
（当前实现只做“新增表”，删除/改列尚未处理）
```

> CSV 数据源：`{"dataset_id": null, "message": "CSV 数据源结构固定，无需同步"}`。

### 3.6 删除数据源

```http
DELETE /api/datasources/{id}
Authorization: Bearer <token>
```

```json
// 200
{"deleted": {"datasources": 1, "datasets": 1, "tables": 2}}
```

```text
级联：datasets → dataset_tables → table_info → column_info → metric_info
      → 物理表（仅 csv）→ Qdrant 点 → ES 文档
```

> Redis 缓存按 key 自然过期（schema_version 变化后不再命中），暂未主动清理。

### 3.7 公开接口示例（免登录）

```http
GET /api/datasources/public/templates
```

```json
// 200
{"templates": [{"name": "订单模板"}, {"name": "会员模板"}]}
```

> 演示“同一模块内混合公开与受保护接口”：公共路由单独一个 `public_router`，不挂 `CurrentUser`。

```http
POST /api/datasets/{dataset_id}/tables
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

```text
name=订单
file=@orders.csv
```

```json
// 201
{
  "dataset_id": 2,
  "table_name": "订单",
  "physical_name": "ds2_t0",
  "rows": 115,
  "columns": 6
}
```

约束：

| 项 | 值 |
| --- | --- |
| 单文件大小 | ≤ 10 MB（建议，未在代码校验） |
| 行数 | ≤ 100,000（已校验） |
| 编码 | UTF-8 / UTF-8-BOM / GBK |
| 列数 | ≤ 200（建议，未校验） |

```json
// 400
{"detail": "文件编码无法识别（支持 UTF-8 / GBK）"}
```

```json
// 400
{"detail": "行数 152340 超过上限 100000，请拆分或使用离线导入"}
```

失败语义：`dataset_id` 不存在或不属于当前用户时返回 400（`数据集不存在`）。

## 5. 问数（SSE）

```http
POST /api/query
Authorization: Bearer <token>
Content-Type: application/json
Accept: text/event-stream
```

```json
{"dataset_id": 1, "question": "上个月华北地区的销售总额是多少"}
```

### 5.1 响应格式

```text
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
```

每帧：

```text
data: <JSON>\n\n
```

| type | 字段 | 说明 |
| --- | --- | --- |
| `progress` | `step`, `status` | `status ∈ running / success / error` |
| `result` | `data`（后续会加 `sql`、`hit_cache`） | 最终结果 |
| `error` | `message` | 整体失败 |

### 5.2 正常流示例

```text
data: {"type":"progress","step":"检查缓存","status":"running"}

data: {"type":"progress","step":"检查缓存","status":"success"}

data: {"type":"progress","step":"召回","status":"running"}

data: {"type":"progress","step":"召回","status":"success"}

data: {"type":"progress","step":"生成SQL","status":"running"}

data: {"type":"progress","step":"生成SQL","status":"success"}

data: {"type":"progress","step":"校验SQL","status":"running"}

data: {"type":"progress","step":"校验SQL","status":"success"}

data: {"type":"progress","step":"执行SQL","status":"running"}

data: {"type":"progress","step":"执行SQL","status":"success"}

data: {"type":"result","data":[{"销售总额":41099.5}]}
```

> 目前图里节点还是占位实现，上述 `step` 名称为目标形态；实际输出以 `app/agent/graph.py` 为准。

### 5.3 失败

```text
data: {"type":"error","message":"模型输出不是合法 SQL"}
```

### 5.4 执行前的错误（非 SSE）

```json
// 404：数据集不存在或不属于当前用户
{"detail": "数据集不存在"}
```

> 参数校验/鉴权失败走普通 JSON；一旦开始流式输出，错误只能以 `error` 帧返回。

### 5.5 客户端读取

```javascript
const res = await fetch("/api/query", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${token}`,
  },
  body: JSON.stringify({dataset_id: 1, question: "..."}),
});

const reader = res.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const {done, value} = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, {stream: true});
  let idx;
  while ((idx = buffer.indexOf("\n\n")) !== -1) {
    const frame = buffer.slice(0, idx);
    buffer = buffer.slice(idx + 2);
    if (frame.startsWith("data: ")) {
      const evt = JSON.parse(frame.slice(6));   // evt.type: progress / result / error
    }
  }
}
```

```bash
curl.exe -N -X POST http://127.0.0.1:8000/api/query ^
  -H "Authorization: Bearer <token>" ^
  -H "Content-Type: application/json" ^
  -d "{\"dataset_id\":1,\"question\":\"上个月华北的销售总额\"}"
```
