# 立项文档

> 一句话：让小电商团队的运营，用自己的数据（CSV 或公司 MySQL），用中文问出 SQL 结果。

## 1. 问题

8 人左右的小电商团队，运营兼做数据分析。数据分两处：历史数据是 ERP 导出的订单、商品、退货三张 CSV；最新的订单在公司的 MySQL 里。

每周要出 2~3 次数据：销量、退货率、品类排名。他们会 Excel 透视表，但遇到「订单 join 商品算品类销量」「退货率的分母到底是订单数还是商品数」这类问题就卡住，换一个口径就要重做一张表；CSV 和 MySQL 两份数据还对不上。

现有替代方案都不行：

- **找数据组**：排期 2~3 天，需求改一次再等一轮；
- **BI 工具**：要先建数据模型，建完口径又变了；接一个新库还要重新配一遍；
- **直接问通用 AI**：字段名经常编造，生成的 SQL 一跑就报错，而且不知道它查的是哪份数据。

结果就是：**数据就在手里，问题却问不出来。**

## 2. 用户与场景

### 用户

运营小陈，会 Excel 透视表，不会 SQL。手里既有 ERP 导出的 CSV，也有公司 MySQL 的只读账号。

### 场景

**场景 1：单表聚合**

> "上个月华北地区的销售总额是多少？"

期望：一个数字 + 实际执行的 SQL。
难点：知道要 SUM，但不确定用「订单金额」还是「实付金额」。

**场景 2：多表关联 + 比率**

> "哪个品类的退货率最高？"

期望：品类 + 退货率排名。
难点：要 join 订单和退货，还要确定分母口径。

**场景 3：时间窗口**

> "最近 7 天每天的订单量。"

期望：按天排列的表格。
难点：日期在 CSV 里是字符串，不确定怎么写范围条件。

**场景 4：重复提问**

> 老板第二天又问同一个问题。

期望：几秒内出结果。
难点：每次都重新调模型，慢且费 token。

**场景 5：接入自己的库**

> 小陈公司的订单在 MySQL 里，他填 host/端口/只读账号，
> 系统读出 12 张表，他问："上周退货最多的商品是哪个？"

期望：自动发现表结构，不用手工导 CSV；结果带 SQL。
难点：

- 表太多，得先判断哪些表相关（召回要过滤 `user_id + datasource_id`）
- 数据库版本不同，日期函数写法不一样，方言要适配
- 只能用只读账号，绝不能执行写操作

## 3. 成功标准

| 指标 | 目标 | 怎么测 |
| --- | --- | --- |
| 执行准确率 | ≥ 70% | 50 条中文评测集，比对生成 SQL 与标准 SQL 的结果集 |
| 缓存命中率 | ≥ 30% | 同一批问题连问两遍，统计 `hit_cache=1` 占比 |
| 未命中延迟 | P95 < 5s | 20 次首次提问，记录 `query_history.latency_ms` |
| 命中延迟 | P95 < 200ms | 重复提问，同上 |
| 跨用户泄漏 | **0 次** | 两个账号互相访问对方的 dataset，必须 404 |
| CSV 上传成功率 | ≥ 95% | 20 个不同编码/脏数据的 CSV |
| 数据源连接成功率 | 100% | 正确配置必成功；错误密码/端口给出可读错误 |
| schema 同步正确率 | ≥ 95% | 随机抽 10 张表，字段数与 `information_schema` 一致 |

## 4. 范围

**做：**

- 注册 / 登录（JWT）
- 数据源管理：新建、测试连接、同步 schema、删除（凭证加密存储）
- 两种数据源：**CSV 上传**（自动建表）与 **MySQL 只读直连**（自动发现表结构）
- 单数据源中文问数（召回 → 生成 → 校验 → 修正 → 只读执行）
- 流式返回进度与结果
- Redis 两级缓存（精确 + 语义）
- 执行审计（谁、什么时候、查了什么 SQL）

**不做：**

- PostgreSQL / ClickHouse / API 类数据源（二期，架构先留接口）
- 任何写操作（只读）
- BI 报表与看板
- 多轮对话（"那上个月呢"）
- 移动端

## 5. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 模型写错 SQL | 结果错 | EXPLAIN 校验 + 一次修正 + 评测集迭代 |
| CSV 质量差（编码/空值/列名脏） | 上传失败或查询错 | 上传时校验并给出可读错误 |
| 跨用户数据泄漏 | 致命 | 所有查询强制 `user_id + dataset_id` 过滤 + 专项测试 |
| 用户凭证泄漏 | 致命 | Fernet 加密存储；接口返回脱敏；日志不打印配置 |
| 连接池耗尽 | 服务不可用 | 每数据源一个池 + LRU 上限（最多缓存 20 个） |
| 语义缓存误命中 | 答非所问 | 阈值 0.95 起步，只缓存执行成功的 SQL |
| 指标口径缺失 | 复杂问题答错 | MVP 只支持字段级聚合，指标二期再做 |

## 6. 分阶段

| 阶段 | 产出 |
| --- | --- |
| 第 1 周 | 骨架 + 登录 + `datasources` 表 + CSV 上传建表 |
| 第 2 周 | 元数据 → Qdrant/ES 索引（带 `user_id + datasource_id` 过滤） |
| 第 3 周 | 问数图：召回 → 生成 → 校验 → 修正 → 执行 |
| 第 4 周 | MySQL 直连：测试连接 + schema 发现 + 方言适配 |
| 第 5 周 | Redis 两级缓存 + 50 条评测集 + 泄漏专项测试 |
| 第 6 周 | SQL 展示 + 审计 + 文档 + 演示 |

## 7. 名词约定

| 名词 | 含义 |
| --- | --- |
| 数据源（datasource） | 用户接入的一个来源：一个 CSV 数据集，或一个 MySQL 库 |
| 数据集（dataset） | 数据源下的一组表，问数的作用域 |
| 元数据 | 表 / 字段 / 指标的说明、样例值、别名 |
| 执行准确率 | 生成 SQL 的结果集与标准 SQL 结果集一致的比例 |
